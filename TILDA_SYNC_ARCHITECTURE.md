# SANSARA ↔ Tilda: правило синхронизации

## Что приходит из Tilda
- externalId / ID offer
- артикул (vendorCode)
- название
- категория
- цена
- первая фотография (`picture`)
- параметры `Качество`, `Размер`, `Срок производства`

## Что никогда не берётся из Tilda как складской источник
- физический остаток SANSARA
- резерв клиента
- доступно клиенту
- выпуск производства
- сборщица
- история прихода
- заказы и их статусы
- скидки и статусы клиентов

Эти данные принадлежат SANSARA и позже будут храниться через Google Sheets + Apps Script API / полноценный backend.

## Правило merge
Основной ключ — SKU/vendorCode. Если он отсутствует, используется externalId offer.
При синхронизации существующей позиции обновляются только описательные поля карточки и цена/изображение. Остаток сохраняется.
Новый товар из Tilda создаётся с остатком 0 и статусом «Под заказ» до первого прихода на склад.

## Настройка тестовой версии
Администратор → Настройки → Каталог Tilda → вставить публичную YML-ссылку → «Синхронизировать каталог».
URL сохраняется локально и проверяется при следующем запуске.

## Коммерческая версия
Прямой YML-sync из админского приложения заменяется/дублируется серверным заданием:
Tilda YML/API → Apps Script/API → Google Sheets/БД → SANSARA API → приложения.
Это исключает обращение каждого клиентского телефона непосредственно к Tilda.
